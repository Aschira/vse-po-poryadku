# Всё по порядку

Уютный список дел в духе бумажного ежедневника: тёплый молочный фон, один цельный «лист» задач, шалфейный зелёный акцент и немного тёплого оранжевого. Только HTML, CSS и JavaScript — без backend, сборки и зависимостей.

## Функции из ТЗ

- добавление задач кнопкой «Добавить» и клавишей Enter;
- отметка выполнения и возврат в невыполненные;
- удаление задачи;
- сохранение после обновления страницы.

## Дополнительно реализовано

- отмена последнего удаления: уведомление «Задача удалена.» с кнопкой «Отменить» (~7 секунд);
- счётчик оставшихся задач с русскими формами («Осталась 1 задача», «Осталось 2 задачи»); когда всё выполнено — «На сегодня всё. Можно выдохнуть»;
- пустое состояние: «Пока чистый лист. С чего начнём?»;
- одинаковые задачи разрешены — у каждой свой стабильный уникальный id (UUID);
- защита данных: текст задач выводится как текст (не HTML), ввод очищается от пробелов, повреждённый localStorage не ломает приложение, при недоступном или переполненном хранилище показывается предупреждение;
- адаптивность 320–1440+, доступность (связанный label, настоящие button/checkbox, aria-подписи, видимый фокус клавиатуры, `prefers-reduced-motion`), контраст цветов WCAG AA;
- дата в шапке — только оформление: не фильтрует и не сбрасывает задачи.

## Как запустить

- открыть `index.html` двойным щелчком, или
- выполнить в папке проекта `python -m http.server 8000` и открыть `http://localhost:8000`.

## Как проверить

- открыть `tests/smoke.html` — 14 автотестов управляют реальным приложением через DOM-события и проверяют модель, DOM и localStorage (список пользователя бэкапится и восстанавливается);
- вручную: Enter в поле, Tab/Space с клавиатуры, кнопка «Отменить» после удаления, обновление страницы.

## Задачи хранятся в localStorage этого браузера

Список живёт в `localStorage` под ключом `todo.tasks.v1` (JSON-массив `{id, text, done}`) и записывается после каждого изменения. Синхронизации между устройствами и браузерами нет: данные привязаны к этому браузеру на этом устройстве и удаляются вместе с данными сайта.

## Какие AI-инструменты реально использовались

- **ZCode CLI (модель GLM от Z.ai)** — код, дизайн и README написаны ассистентом в диалоге с человеком; направление дизайна («бумажный ежедневник») выбрал человек.
- **Автоматизация браузера ZCode** — прогон smoke-тестов и проверок вёрстки в управляемом браузере.
- В самом приложении AI-функций нет.
